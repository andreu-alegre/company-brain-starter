# Public template, private work brain

Everything in this repository, its branches, pull requests and Git history is public.
Keep the template generic. Examples must be fictional and clearly labeled.

Your completed brain belongs in a workspace you control with an appropriate audience:
a private folder, private assistant project or new private repository. Access and data
processing still follow your organization's rules. A folder name or label does not
restrict access, and a local folder may itself be synced or shared.

Use short, relevant summaries with sources and dates. Do not include passwords, tokens,
credentials, private account configuration, raw transcripts, CRM dumps, contact lists,
unnecessary personal information or evaluations of people. Describe collaborators by
their responsibility and how work is coordinated.

Choose external sources and scope before analysis. A public template does not grant
access to any company's systems. A connector provides capabilities, not blanket
authorization to read everything or act in someone's name.

Review both files and history before sharing a copy. `.gitignore` is a convenience,
not a security boundary; it does not remove files already committed. Do not put your
completed brain in a public fork, issue or pull request.
