# Contributing

Improvements should make the first experience easier or the context more reliable.
Keep the only required entry point a copyable starter prompt. Advanced instructions
belong behind it. Keep the English and Spanish README prompts equivalent.

Use a branch and pull request. Describe the user problem, resulting behavior and
validation. The maintainer reviews and approves merges; draft proposals stay drafts.
Never add real company data, recipient handoffs, credentials or personal work brains.
Use clearly fictional examples and report template issues without private attachments.

Before proposing a change, check internal links, relative skill symlinks, skill
frontmatter and the complete diff. A static check does not prove useful behavior:
try a small representative task in a private environment and describe its limits.
Do not add dependencies or tests that merely repeat the wording of instructions.

Canonical workflows live in `skills/`. Claude Code and Codex adapters point there.
Keep domain guidance independent of tool names; surface-specific setup stays optional.
